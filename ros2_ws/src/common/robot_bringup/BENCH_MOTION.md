# 悬空底盘脉冲工具

本工具仅用于轮子全部离地后的短时调试。它不会自动使能，也不会自动重复脉冲。
命令接口保持不变：必须指定 --wheels-raised，--forward 或 --turn 二选一；
最大平移命令 0.05 m/s、最大偏航命令 0.2 rad/s、持续时间 0.1–2 秒。

## 启动和运行保护

- 必须同时收到 /ec/wheel/odom 原始反馈与 /odom/wheel 适配反馈。
- 两路均检查数值有限、odom/base_link 坐标系、单位四元数、非零且递增的时间戳。
  消息到达时已有的传输延迟也计入 0.5 秒新鲜度上限；时钟倒退/未来戳拒绝。
- 起步前两路各需要至少连续两个新静止样本：平移不超过 0.01 m/s、
  偏航不超过 0.03 rad/s。已有未知运动时不启动。
- 同时要求 EC/adapter 状态有效、手动使能已生效、无急停或故障、
  /cmd_vel 只有本工具一个发布者，且 stop/disarm 服务可用。
- 任一路平移速度 hypot(vx, vy) 超过 0.10 m/s，或 |wz| 超过 0.4 rad/s，
  立即锁存中止并发零。这是固定的异常保护值（最大允许命令的两倍），
  **不是速度标定、闭环误差容许值或真实速度准确性的证明**。没有绕过开关。
- 丢失/过期/重复/无效反馈、使能变化、竞争发布者、SIGINT/SIGTERM 也中止本次操作。

## 收尾与结果

正常结束和异常退出都会发零，并各请求一次 /ec_bridge/stop 与
/ec_bridge/set_arm（data=false）。两项请求并行发送，避免一个回复延迟另一个。
随后最多等待 3 秒，要求服务成功、新 EC 状态报告已解除使能、双源新静止反馈
持续至少 0.2 秒。无法确认时结果失败；不会将“已发送 stop”当作“已停稳”。

终端最后输出一行 BENCH_REPORT JSON，保存命令、峰值反馈、异常原因、
stop/disarm 的发送与回应及反馈验证。静止反馈仍是遥测证据，不替代肉眼确认或机械急停。

2026-11-05 曾出现 0.03 m/s 指令对应约 0.24–0.314 m/s 反馈。
该异常的轮径/编码器/固件单位或速度闭环原因尚未确认；增加保护不代表原因已修复，
在核实原因前不继续真机脉冲测试。

## EC 口头最低速度信息

用户后续转述 EC 同学称“PWM 电机最小速度约 0.31 m/s”，但不知道该数值来自
落地实测、悬空轮速还是参数换算。它与此前遥测峰值相近，属于待核对线索，
不能视为地面速度标定或全部根因已确认。

当前真机差速 NAV 的最大前进速度为 0.15 m/s；差速入架使用 +0.08 / -0.06 m/s
范围，并随位置误差减速，要求位置误差小于 8 mm 才进入到位保持。
若 0.31 m/s 确为整车最低可控速度，这些低速控制前提需要重新解决。
提高最高速度、把小指令抬升至 0.31 或放宽 bench 上限，均不能直接证明精确入架和停止可行。

本工具保持命令 0.05 m/s、回报 0.10 m/s 的现有限值，没有绕过开关。
无线网络、SSH 和静态传感器检查可单独准备；改为无线不自动使能底盘，也不改变本工具的使用边界。

## 无硬件回归

source ROS 2 Jazzy 和项目工作区后，从仓库根目录运行：

```bash
python3 -m unittest discover -s ros2_ws/src/common/tests -p test_bench_motion.py -v
python3 ros2_ws/src/common/tests/ros_bench_motion.py output/bench-no-hardware
```

第二项固定使用 LOCALHOST ROS 域 210，只运行模拟反馈/服务和工具子进程，
不启动 EC bridge、不打开串口。覆盖正常脉冲、两路超速、偏航超速、陈旧/非有限/
重复时间戳、缺路、起步已有运动、SIGINT/SIGTERM 以及 disarm 失败。

2026-11-05 已保存的结果为 20 项单元检查、12 项 ROS 模拟回归通过；证据位于
仓库 `output/pi_full_validation_20261105/bench_guard_verified/`。这属于无硬件保护验证，
没有重复真实异常脉冲，也不代表 0.31 m/s 已通过实车验收。
