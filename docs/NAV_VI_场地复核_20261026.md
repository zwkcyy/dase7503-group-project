## 2. 对照原始课程文件后的处理

来源：用户提供的《2. DASE7503 Group Project_QR Code and Gamefield.pdf》第 2、3 页。

| 项目 | 采用的数据或处理 |
|---|---|
| 场地内尺寸 | 3020 × 2000 mm；ROS 转成 3.02 × 2.00 m |
| 起点区域 | x=[2420,3020]，y=[600,1400] mm |
| 终点区域 | x=[0,800]，y=[300,1700] mm |
| 起始摆放 | 区域中心 (2720,1000) mm，yaw=π；这是 NAV 摆放约定 |
| 展示方向 | 起点在下、终点在上；不改变 ROS 地图坐标定义 |
| 货架身份与位置 | 第 3 页有 A/B/C/D；第 2 页尺寸图没有标签。模拟位置按第 3 页估计，明确标注为非实测 |
| 中央障碍物 | 课程展示中移除；原回归场景仍保留该测试障碍 |
| 颜色和信息 | 灰色地面、绿色终点、蓝色起点、黄色货架任务点；显示实时位置、规划路线、确认图像、完整扫码序列与进度 |

单一场景文件为 `robot_simulation/config/course_layout.yaml`。启动时由它生成本轮的
仿真世界、任务参数、静态墙体地图和显示布局；车体轮廓也读取导航的同一份几何快照。
界面使用 `/simulation/pose`、`/plan`、`/mission/status`、`/qr/data` 和实际图像消息。
没有播放预制的运动动画，也没有跳过二维码解码直接填写确认结果。

入口已明确：

```bash
bash scripts/nav.sh demo             # 课程场地窗口，实际 Nav2 与 QR 解码
bash scripts/nav.sh regression-demo  # 中央障碍回归场景，RViz 与扫码窗口
bash scripts/nav.sh cad              # 交付 CAD 模型与坐标参考
```

## 3. 复核发现并修正的问题

| 问题 | 修改及防回归措施 |
|---|---|
| 课程展示误用了回归场景 | 默认 demo 改为课程场景；保留并明确命名 regression-demo |
| 地图、任务点、画面可能各自使用默认值 | 从同一场景生成参数和地图；新增尺寸、方向、标签、位置来源及越界检查 |
| 显示车辆轮廓写死 | 改为读取与导航共用的 geometry.yaml |
| 中文地图路径被破坏 | 原来先重写 YAML 再执行 launch 字符替换，会破坏 Unicode 转义；改为先展开模板，再重写 YAML；新增中文及空格路径检查 |
| EC 遥测超时被延后 | 新鲜度计算包含传输时间；接近过期的报文不会重新得到完整超时时间 |
| 无效里程计姿态仍被转发 | 增加单位四元数检查；非法值拒绝转发 |
| 自动检查提前创建运行目录 | 截图目录改在收到实际图像后创建；保持启动器对旧运行目录的防覆盖保护 |
| 文档入口与实现不一致 | 同步无窗口参数、包数量、默认运行目录、已接入 EC 状态与检查命令 |

首轮课程检查的目录冲突和中文路径失败日志已保留于本机
`output/course-audit-20261026/`，没有混入最终成功证据。
