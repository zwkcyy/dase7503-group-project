### 出现异常：先使用现场硬件急停，确认实物已停

下面两条是不同的软件请求，可在终端 C 执行。服务有回复也必须观察实际车轮和升降机构，不能把回复文字当作物理停止确认。

```

  '{data: true}'
```

## 06 先接通 EC，不允许动作

阶段 1 · A 保持通信；C 观察 · 尚未启动导航

### 1  C：找串口，填好第 5 页的 EC_PORT

```bash
ls -l /dev/serial/by-id/
```

没有 by-id 时检查 /dev/ttyACM* 或 /dev/ttyUSB*。权限不足：sudo usermod -aG dialout "$USER"，然后重新登录。确保只有一个程序打开该串口。

### 2  A：启动并保持运行

```bash
cd "$REPO"
bash scripts/nav.sh ec start_bridge:=true \
  port:="$EC_PORT" baudrate:="$EC_BAUD" \
  enable_motion:=false enable_lift:=false
```

### 3  C：读取状态（每条收到一条后自动结束）

```bash
ros2 topic echo /ec_bridge/status --once
ros2 topic echo /ec_adapter/status --once
ros2 topic echo /ec/lift_state --once
ros2 topic echo /odom/wheel --once
ros2 topic echo /imu/data_raw --once
```

| 看到这些才算通过 | 没有看到时查什么 |
| --- | --- |
| open=true，link_ok=true；接收计数增加 | 供电、串口、权限、波特率、固件协议 |
| ec_fault=0；状态不是 null | null 是缺失或过期的 84 帧，不是正常值 |
| telemetry_ready=true | 查看 issues；检查时间戳、帧名、里程计和 IMU |
| lift_completion_source = ec_timed_state_transition | 若不是，检查是否加载了旧配置或旧安装目录 |
| allow_lateral_motion=false | 桥、适配器都应禁用横移；关闭旧节点 |

命令一直等待表示尚未收到消息，可 Ctrl+C 返回处理。坐标：x 前、y 左、z 上；正 yaw 为俯视逆时针。ROS 使用 m、rad、m/s、rad/s。

## 08 空载升降，核对实际反馈

阶段 3 · 运动禁用 · 升降空载且行程内无阻挡

### 1  A：结束旧进程，按本页权限重启

```bash

```

C 按第 7 页使能并确认状态。/ec/lift_state 应与实物对应：底端 0、顶端 1。初始在顶端则先下降。

### 2  F：持续看任务侧反馈，保持运行

```bash

```

### 3  C：实际在底端时，只发一次上升

```bash
ros2 topic pub --once /lift_cmd std_msgs/msg/Int8 '{data: 1}'
```

**上升通过**：F 先显示 -1；本次 F0 回执和 EC 从 0 到 1 的新变化齐全后，才显示 1。观察机构确已到顶停止；主机不会仅等三秒就假报成功。

### 4  C：实物停止且反馈 1 后，只发一次下降

```bash
ros2 topic pub --once /lift_cmd std_msgs/msg/Int8 '{data: 0}'
```

下降应显示 -1 → 0，且机构实际回底端。同端点重复同向指令会拒绝；不得连续发布或用人工 /lift_state 跳过反馈。

### 5  C：在空载条件下核对停止能力

```bash

```

## 19 故障发生时怎么恢复

阶段 10 · 先在架空或空载受控条件下演练

| 看到什么 | 先做什么 / 怎样恢复 |
| --- | --- |
| 串口断开 | 确认 EC 看门狗实际停车；重连后只请求状态，不重放旧升降、不自动使能。核对实际位置后重新使能并发新指令 |
| F0 回执丢失或拒绝 | 未确认指令最多重发 5 次，总有效期 2 s；不报成功。检查 EC 回执，不增加无限重试 |
| 升降反馈中断 | 不算完成；实物可能还在走原行程。先稳定机构，确认位置，再清除任务并重启 |
| 错码或相机断流 | 扫码阶段超时应 ERROR；不能用上一次结果冒充。恢复图像、检查实际码，再重新开始 |
| 雷达 / TF / 里程计过期 | motion_guard 应输出零速度并给原因；修复驱动、时间戳和 TF，不关闭保护 |
| 软件急停 | /nav/emergency_stop 会锁存。按第 2 页确认实际停止，查原因后重启 NAV |
| 任务 ERROR 或超时 | 不会自动放下正在搬运的货架。先稳住实物与机构，再布置场地、恢复反馈、重启任务 |

**每次恢复前都要检查**：实际静止、机构稳定、故障已排除、状态新鲜。EC 急停释放按实际固件规则操作，随后核对 ec_armed / ec_estop / ec_fault；不直接释放后继续跑旧任务。

升降停止能力有限，软件退出不保证中途停住。升降故障先空载演练，不做载货断电试验。EC 急停与看门狗的物理效果必须现场记录。
