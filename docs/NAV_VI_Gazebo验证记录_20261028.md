# NAV／VI：Gazebo 三维仿真运行与验证

日期：2026-10-28。环境：本机 WSL 2、Ubuntu 24.04、ROS 2 Jazzy、Gazebo Harmonic 8.15.0、DART、Ogre2。

## 1. 已经接通的内容

新增 `robot_gazebo` 包，完整流程为：启动自检 → 渲染相机识别 START → Nav2 导航 → 实际识别货架码 → 低速入架 → 物理抬升 → 载货导航 → 对位并实际识别 END → 放下 → 空载退出。重复四架。

- 使用机械组原始 CAD 外观和原始尺寸；未修改 CAD、EC 子仓库或跨组消息契约。
- 四个麦克纳姆轮关节驱动小车，轮里程计来自轮关节积分；EKF 和 AMCL 负责定位。
- 货架由重力、托盘接触和摩擦抬起及搬运，没有跟随小车的位置强制设置。
- 四个货架始终保留在物理世界中，已经放下的货架也继续作为障碍物。
- 相机图像由三维场景实时渲染，二维码存在于场地与货架上；支持透视、遮挡、多码同框。
- 激光、IMU、相机和升降反馈已接入现有导航、视觉和任务节点。
- 取货后直接由 Nav2 规划载货路线；放下后的直线退出保留，以清除货架腿和后续转向范围。
- 增加真实接触记录、速度指令超时停车、接触锁定停车，以及通信桥／执行适配器退出后自动关闭仿真。

## 2. 本机怎么打开

在 Ubuntu 终端执行（不是 Windows PowerShell）：

```bash
cd '/mnt/e/研究生/sem1课程/7503/dase7503-group-project'
bash scripts/nav.sh gazebo
```

本机依赖已安装、九个包已编译。打开后等待自检，任务会自动开始。
需要同时显示相机和扫码窗口时：

```bash
bash scripts/nav.sh gazebo show_results:=true
```

停止整套程序：在启动终端按 **Ctrl+C**。关闭 Gazebo 窗口只关闭画面，服务器仍可能运行。
需要重新开始时，停止整套程序后重新启动；不要在任务中点 Gazebo 的重置按钮。
一次只运行一套演示。默认使用仅本机的 ROS 域 75 和独立 Gazebo 分区。

其他已装 ROS 2 Jazzy 的 Ubuntu 24.04 电脑首次使用：

```bash
bash scripts/nav.sh install
bash scripts/nav.sh gazebo-install
bash scripts/nav.sh build
bash scripts/nav.sh gazebo
```

普通编译和启动不自动执行测试。原来的 `bash scripts/nav.sh demo` 仍是平面回归仿真。

## 3. 验证方法和记录

每次使用一个新的输出目录：

```bash
bash scripts/nav.sh gazebo-check --output output/gazebo-my-run
bash scripts/nav.sh gazebo-faults --output output/gazebo-my-fault-check
```

第一条执行完整任务并独立检查十四项结果：完成四架、接触监测有效、零非预期接触、无急停、八次升降反馈、九次真实扫码、四次空载退出、180 秒任务限制、轨迹连续、落位误差与整架入区、货架不重叠、搬运离地、姿态稳定、实际货架处于载货规划轮廓内。

计时从 START 确认到第四架退出完成，使用**仿真时间**；电脑实际等待时间包含启动和运行开销，不能混称比赛用时。审计不会仅凭终端的 COMPLETE 判断通过。

## 4. 这轮找到并修复的问题

1. 三维二维码材质、接触主题格式与接触实体名称读取不匹配：修复并确认真实图像和接触消息持续到达。
2. 理想渲染激光与原实车定位参数不匹配：单独生成 Gazebo 定位参数，未覆盖实车默认配置。
3. 小码及多个码同框时漏检／误选：增加限定次数的区域及放大重试；优先选择真正解码出的当前目标，仍拒绝错误内容。
4. FLOOR 标签与 START 二维码文件重名导致纹理覆盖：使用不同资产文件名前缀。
5. 1 kg 场景下升降静差约 1.07 mm，超出 1 mm 到位标准而超时：调整力控制积分参数和积分限幅，保留到位标准；之后重载完整运行通过。
6. 仿真快慢影响任务限时：任务与对位采用仿真时间，实机继续使用单调时钟；指令通信看门狗保持墙钟时间。
7. 初始三维视角过远、插件面板遮挡：整理 GUI 布局并实看场地、车辆、货架和二维码。
8. 启动阶段 ROS 时钟桥和执行回调不同步，导致记录器漏掉部分时间点：改为缓存 Gazebo 传输层位姿采样并保留原始物理时间戳，新增缓存溢出失败检查；没有插值填补记录。

失败运行保留在同一输出根目录，不覆盖、不算作成功。例如 `final-heavy` 是升降到位超时，`final-heavy-02` 是小码漏检；后续修正后重跑。
`release-baseline` 虽完成四架且没有非预期接触，但启动阶段 WAIT_START 的最大记录间隔为 0.272 秒，超过独立审计的 0.2 秒上限，因此仍计为未通过。没有放宽检查阈值。
`release-baseline-02` 同样因启动阶段 0.240 秒间隔未通过；随后针对记录器修正。原失败记录保留。
修正后的 `release-baseline-03` 十四项审计全部通过，最大原始位姿采样间隔 0.017 秒、缓存丢弃 0 条、非预期接触 0，累计收到 1,141,154 条接触消息。

## 5. 已采用的假设及实物边界

| 项目 | 当前采用值／方法 | 需要实物确认的内容 |
|---|---|---|
| 场地／货架 | 场地 3020×2000 mm、墙高 500 mm；货架总高 232.5 mm、深 140 mm | 现场摆放和实际尺寸 |
| 货架未标注项 | 宽 400 mm、腿 15 mm、板厚 6 mm、总质量 0.5 kg | 板下净高、开口、质量及摩擦 |
| 机械模型 | 原始 CAD 尺寸、原质量；组件包围盒碰撞与近似惯量 | 真实质心、惯量、轮滑、传动响应 |
| 升降 | 等效直线关节，行程 25 mm、目标斜坡 15 mm/s、限力 80 N | 实际连杆／舵机行程、速度、力矩及完成反馈 |
| 雷达 | 建议水平位置 `[145, 0, 70] mm` | 实际测量中心和水平安装；原 CAD 雷达方向倒置 |
| 相机 | CAD 平移位置，建议上仰 0.35 rad；640×480、水平视场 1.4 rad | 真实安装角度、内参、畸变和标定 |
| IMU | 暂定 `[0, 0, 50] mm`、水平轴系 | 实际轴向、坐标和时间戳 |
| 二维码 | DEMO 内容；货架码 70 mm、终点码 100 mm，固定实体位置 | 正式码内容、实际尺寸及位置 |

**机械问题仍存在：原 CAD 高约 223.04 mm，高于课程 180 mm 限高。** 仿真没有缩小模型来掩盖该问题。按目前假设板厚计算，静态托盘到货架板下只有约 **3.46 mm** 间隙；需要测量实物并解决机械尺寸／最低姿态问题。

仿真通过覆盖的是已保存模型和已测试条件。真正上车前仍要检查传感器标定、EC 实际驱动和反馈、地面摩擦、载荷、制动距离、正式场地尺寸及二维码。不能把零仿真接触当作实物永不碰撞的保证。
