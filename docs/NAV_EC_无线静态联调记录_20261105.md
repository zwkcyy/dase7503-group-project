## 3. 本轮修复

第一次采集和回传指标通过，但雷达退出时出现 `FD_SETSIZE` 越界 / `Aborted`，进程退出码 250。首轮应记为**数据检查通过、正常收尾失败**，原始证据保留。

原因是 SDK 在接收线程退出前先关闭串口，使线程可能使用已经变为 `-1` 的文件描述符。修复包括：

1. 设置线程退出标志，等待接收线程退出，再关闭串口；等待返回后再次检查退出标志。
2. 将串口积压字节的单次读取长度限制到接收缓冲区容量，余下数据留待下一轮读取。
3. 正确处理 `read()` 的负返回值，避免变成巨大的无符号长度。
4. 加强测试工具收尾判据：异常退出、强制 SIGKILL 或残留进程均使整体检查失败。

修复已在 Pi 编译；**五次真实雷达启动、收到至少 20 帧后停止的检查全部正常退出**，随后两分钟并发复测也正常结束。接收边界修复经过源码与 C++11 语法检查；本轮未进行硬件拔插、串口错误或最大积压注入测试。

可复用补丁：[oradar-ms200-serial-lifecycle.patch](../scripts/patches/oradar-ms200-serial-lifecycle.patch)。补丁基于本轮使用的 Oradar MS200 SDK，只改变线程退出和读取边界；部署前需在目标源码中 `git apply --check`，不能重复应用。扫描角度修复来自此前已部署版本。
