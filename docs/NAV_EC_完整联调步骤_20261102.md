### 横向速度由 NAV 确定

本轮真机采用前后移动和转向，vy = 0。麦克纳姆轮的机械结构不变；这是与当前 EC 接口兼容的软件运行方式。Nav2 使用 DiffDrive，AMCL 使用 DifferentialMotionModel，速度平滑器禁用横移。

入架和退出采用已经对准后的低速直行，不通过横移修正。入架横向偏差达到 8 mm 或朝向误差达到 0.018 rad（约 1°）时拒绝继续；必须在货架外重对准。它是软件门槛，实际允许误差还要小于实测通道余量。

| 环节 | 本轮设置 |
| --- | --- |
| 空载/载货通行 | 先转到路线方向再前进；真机前进上限 0.15 m/s，转向上限 0.4 rad/s。 |
| 入架/退出 | 直行入架最高 0.08 m/s，退出最高 0.06 m/s；保留原倒车距离与雷达可见性保护。 |
| 意外横移指令 | 整条指令拒绝并输出零速度；不只删掉 vy 后继续执行其余分量。 |
| 当前验证范围 | 本轮做代码修改与编译，不代表真机验收通过；原 Omni 仿真结果不能替代新模式实测。 |

### 终端 B：逐项观察

```bash
source ~/dase7503-commissioning/session.env
ros2 topic echo /ec_bridge/status --once
ros2 topic echo /ec_adapter/status --once
ros2 topic echo /ec/lift_state --once
ros2 topic echo /odom/wheel --once
ros2 topic echo /imu/data_raw --once
```

| 通过条件 | 不符合时 |
| --- | --- |
| open=true、link_ok=true，接收计数增加 | 检查供电、串口、权限、波特率、固件协议；不要先启动导航。 |

| lift_completion_source=ec_timed_state_transition | 否则仍在使用旧人工配置或旧安装目录。 |
| allow_lateral_motion=false | 桥和适配器应一致；旧节点必须退出。 |

坐标约定：base_link 的 x 向前、y 向左、z 向上；正 yaw 从上方看逆时针。ROS 接口单位是 m、rad、m/s、rad/s。

## 05  架空轮测、方向与里程计

仅在四轮已可靠离地时使用 bench_motion。该工具限制速度、时长，要求新鲜 EC 状态，并拒绝与另一个 /cmd_vel 发布者同时运行；它不经过地面避障流程，不能拿来驾驶落地车辆。

### 重启终端 A，打开运动入口

```bash

  enable_motion:=true enable_lift:=false
```

### 终端 B：使能并核实 EC 状态

```bash
ros2 service call /ec_bridge/set_arm std_srvs/srv/SetBool \
  '{data: true}'
ros2 topic echo /ec_bridge/status --once
```

须看到 ec_armed=true、ec_estop=false、ec_fault=0。frame sent 只证明写入成功，不证明已使能；如果状态立即掉回未使能，记录固件看门狗行为并处理，不能增加假保活掩盖故障。

### 每次一个短脉冲，观察停止后再发下一个

```bash
ros2 run robot_bringup bench_motion \
  --wheels-raised --forward 0.04 --seconds 1
ros2 run robot_bringup bench_motion \
  --wheels-raised --forward -0.04 --seconds 1
ros2 run robot_bringup bench_motion \
  --wheels-raised --turn 0.15 --seconds 1
ros2 run robot_bringup bench_motion \
  --wheels-raised --turn -0.15 --seconds 1
```

观察四轮组合方向是否对应前进/后退/左右转；轮式里程计 vx、wz 的符号应相符。离地轮测时车身未旋转，IMU yaw rate 接近零是正常的，不能要求它与架空轮速相同。

随后解除使能，人工推动车身测里程计方向和距离，并手动缓慢左右转动检查 IMU gz 正负号；车体逆时针时 gz 应为正。传感器轴不对时修正 EC/IMU 旋转参数，不靠改变导航坐标轴掩盖。

## 06  升降闭环与停止能力

四轮仍不允许驱动车辆，升降空载。重启终端 A 为 enable_motion:=false、enable_lift:=true。使能后检查有效状态，机构实际位置必须与 EC 的 0/1 对应。

```bash
cd "$REPO"
bash scripts/nav.sh ec start_bridge:=true port:="$EC_PORT" \
  enable_motion:=false enable_lift:=true
```

终端 B 使能：沿用上一页 set_arm 命令。终端 C 在加载环境后观察任务侧反馈；B 再发一次上升。

```bash
# 终端 C
ros2 topic echo /lift_state
# 终端 B：当前必须在底端 0
ros2 topic pub --once /lift_cmd std_msgs/msg/Int8 '{data: 1}'
```

通过条件：先收到 -1；本次 F0 接受回执到达，且 EC 状态由 0 变为 1，才收到 1。固件声明约 3 s 行程，树莓派不会等三秒后自行假报完成。

```bash
# 观察实物停止且反馈为 1 后，B 再发送
ros2 topic pub --once /lift_cmd std_msgs/msg/Int8 '{data: 0}'
ros2 topic echo /ec_adapter/status --once
ros2 topic echo /ec_bridge/status --once
```

下降应为 -1 → 0。若初始在顶端，先下降再上升。同一端点的重复同向请求会拒绝；不要持续发布升降命令。没有 F0、只有旧状态、反馈中断或报故障时，不得当作完成。

### 停止服务的真实含义

```bash
ros2 service call /ec_adapter/stop_lift std_srvs/srv/Trigger '{}'
```

## 14  故障与恢复演练

先在架空轮测或空载受控场地演练；升降故障先空载。不要以载货断电来验证保持力，也不要在软件未知时依赖电脑上的服务替代硬件急停。

| 故障 | 应有表现 / 恢复方法 |
| --- | --- |
| 串口断开 | EC 自身看门狗应停车；适配器取消待升降完成。重连只请求状态，不重发旧升降、不自动使能。重新观察实际状态后人工使能与新发指令。 |
| F0 丢失 / 拒绝 | 未确认的升降最多重发 5 次且总有效期 2 s；失败不报完成。查 EC 回执，不把无限重发当修复。 |
| 升降反馈中断 | 不得发布成功；现场核对实际位置，清除任务并重启。机构可能仍在执行旧动作。 |
| 相机断流 / 错码 | 扫码阶段超时进入 ERROR；不能用上一张码冒充本次结果。恢复图像后重新开始任务。 |
| 雷达 / TF / 里程计过期 | motion_guard 输出零速并说明原因。修复时间戳、驱动和 TF，不关闭保护。 |
| 软件急停 | /nav/emergency_stop 锁存停车；查原因后重启 NAV。EC /ec_bridge/estop 为另一层，硬件效果需实测。 |
| 任务 ERROR / 超时 | 不自动放下正在搬运的货架。先稳定实物和机构，再重新布置、恢复反馈、重启任务。 |

```bash
# 软件停车（NAV 已运行时）
ros2 service call /nav/emergency_stop std_srvs/srv/Trigger '{}'
# EC 急停请求；frame sent 不等于物理动作已确认
ros2 service call /ec_bridge/estop std_srvs/srv/SetBool \
  '{data: true}'
# 结束：机构静止后解除使能
ros2 service call /ec_bridge/set_arm std_srvs/srv/SetBool \
  '{data: false}'
```

急停后不要直接发送释放指令继续跑。先确认实际停止、机构稳定、故障已排除，再按 EC 固件规定释放急停；重新检查 ec_armed / ec_estop / ec_fault。
